What's new in 4.0 rc.1 (Increment 8)

Get your work out and bring existing work in: export a book as PDF, USFM or a Scripture Burrito, export stories as Markdown, PDF or a burrito, and import translationCore 3, USFM and Scripture Burrito files. Plus project Settings on the Home card, new books opening in Understand, English helps v91 in the box, and Spacing and Paper size for printing.

What arrived

Export (Increment 8)

All exports start from Check › Community Checking › Open → › Export. After the save window closes, the panel says "Saved <file name>". If you cancel, no message appears.

  • Bible book: Export PDF, USFM, aligned, USFM, plain and Scripture Burrito (.zip). See Export a book as PDF, Export a book as USFM and Export a project as a Scripture Burrito.
  • Open Bible Stories: Export PDF (with or without pictures), Story Markdown (.zip) and Scripture Burrito (.zip). See Export stories as PDF or Markdown.
  • A book with nothing drafted is not printed: "… has no drafted verse yet, so the PDF has nothing to print. Draft at least one verse of this book, then export the PDF again."

Import

+ Add a project › Import a project makes a new project from a translationCore 3 project (tC3) zip, USFM files or a Scripture Burrito. See Import a project.

  • The review shows the books, the License, Details and Missing verses checks, and what carries over (alignments and checking decisions from translationCore 3 or tC4).
  • Details warns in orange when the language code is missing ("The language code is missing or not valid. Enter it below.") and turns green once the code is filled in.
  • A Bible name that is already used is refused until you change it.
  • Damaged files are refused with a reason and a code, such as import.damaged.usfm-parse or import.damaged.truncated, and nothing is created. See Messages that protect your project.
  • The new card carries an Imported badge.

Also new in this increment

  • Settings on the card: the Project settings button left the top bar. Click Settings on a project's Home card instead (issue #505). See Project settings.
  • A cleaner top bar: no server name such as "QA server", and no "Internet"/"Local" label. Cards say "Only on this computer" or "Shared at owner/repo" (issue #506). See The Home screen.
  • New books open in Understand, so you read before you draft. After that a book reopens in the mode you used last (issue #507). See The three modes.
  • English helps v91 in the box: a new project drafts from "unfoldingWord ULT + UST v91 — installed with the app" and checks against the v91 notes and words, with no download (issue #504). See Add a book.
  • Check works across project kinds: moving between a Bible project and a stories project no longer says "This book is not in the pinned resource"; each project uses its own notes and words (issue #434). See Choose a checking tool and Check a story.
  • Page setup for printing: Spacing (Single or Double) and Paper size (A4 or Letter) for Bible books; Layout (Pictures above or Pictures wrapped) for stories (issues #142 and #381). See Community Checking preview and Story preview and export.
  • "Saved" message after export: it appears only when the file is really saved (issue #382).
  • Window › Reload: the desktop app's Window menu has Reload (Ctrl+R) and Force Reload (Ctrl+Shift+R), to reload the screen without quitting (issue #435).
  • Resume returns to the last mode, including the checking tool you were using. See Resume where you left off.

Check for updates: only the texts your books need (issue #438)

On Home, click Settings on the project card, then Manage source texts →. The project opens with Get source texts. Under Pinned resources, click Check for updates (click Continue if "Use the internet?" appears). See Update pinned helps and Update scripture texts.

  • Each help set shows ✓ Up to date or "Upgrade 4 resource(s)" with each move, for example en_tn v86 → v91 · 2026-09-26.
  • Scripture texts lists a Gateway Bible row for each gateway text that has a newer release, for example en_ult v89 → v91, each with Upgrade.
  • An Original-language text row appears only when one of the project's books needs that text and the project pins an older release. A Titus-only project (New Testament) gets no Hebrew row. "Equipo Ejemplo — Tito y Jonás" has Jonah (Old Testament) and pins an older Hebrew text, so it showed Original-language text hbo_uhb v2.1.30 → v3.0.0 · 2026-08-14.
  • A project made with this build is current: "✓ Every scripture text is up to date", and both English sets say ✓ Up to date.

Changing the checking language keeps the checks that still match (issue #448)

On Home, click Settings on the card and choose another language under Checking language. Its notes must be on this computer first (see Download source texts). See Change the checking language.

  • The dialog says how many decisions are affected and what happens to them, for example "Change checking language to Spanish (Latin American)?", "3 decisions in Titus were made against the notes you are leaving." and "Titus · Translation Notes: 0 carried over, 3 to check again".
  • A decision carries over only when the new notes have a matching check (the same note on the same words). The Spanish notes can split one English note into several, so a decision on the English note has nothing to carry over to. The count can then be 0. Those checks come back as work; nothing is deleted.
  • After the change, Check counts the carried-over decisions. You can decide every check again, including one that came back, and it saves: the indicator shows Saved.

translationCore 3 import, and a way back from a blank window (issue #435)

  • A translationCore 3 project import shows an orange Resource versions check on the review. Choose Look up on Door43 (it needs the internet) or Use installed versions; Import as a new Bible stays off until you choose. With Door43 the review says "The versions this project used were found: …". See Import a project.
  • If a screen cannot be drawn, tC4 now shows "This screen could not be shown." with a Back to Home button, instead of a white window.
  • The desktop app's Window menu has Reload (Ctrl+R) and Force Reload (Ctrl+Shift+R). Window › Reload brings the app back to Home without quitting, and your projects stay as they were. See If the app closed unexpectedly.

Known issues in this build

  • A section comment written in Understand shows as "VERSE 1" (its first verse) in Translate › Comments.
  • After you join verses into a span, the book's percentage can drop (for example from 7% to 4%), and the Resume banner can still name the old verse.
  • The "… was imported" message does not close by itself, and its ✕ does not always close it. Only the newest import keeps the Imported badge.
  • In USFM exports, the \h, \toc and \mt lines carry the book code (TIT), not the book name.
  • On Linux, the save window's Save and Cancel buttons can be off-screen: press Enter to save, Esc to cancel.
  • In a stories project, after you save a frame, the Stories rail shows plain "Story 2", "Story 3"… with no titles or percentages until you go back to Home.
  • The same language is named two ways: "Español (Latinoamérica)" in the language lists, and "Spanish (Latin American)" in the sentence under Checking language, the change dialog and the "… is ready" message. The dialog's button names the code instead: "Keep en".
